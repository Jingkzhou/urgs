## 1. 系统架构概览

URGS 是一个面向企业级资源治理与调度的多模块系统，由以下服务组成：

```
                         ┌──────────────┐
                         │   用户浏览器   │
                         └──────┬───────┘
                                │ :18080 (Nginx)
                         ┌──────▼───────┐
                         │    Nginx      │  静态文件 + 反向代理
                         └──┬───┬───┬──┘
                            │   │   │
               ┌────────────┼───┼───┼────────────┐
               │            │   │   │            │
         ┌─────▼─────┐ ┌───▼───▼──┐ ┌▼──────┐ ┌──▼──────┐
         │ Web (静态) │ │ API      │ │ RAG   │ │ Agent   │
         │           │ │ :8080    │ │ :8001 │ │ :8002   │
         └───────────┘ └──┬───┬──┘ └──┬───┘ └─┬───┬───┘
                          │   │       │       │   │
                ┌─────────▼┐ ┌▼─────┐│  ┌─────▼─┐┌──▼───┐
                │ MySQL    │ │Neo4j ││  │PG(Agent)│Redis │
                │ (主库)    │ │(图谱)││  │        │      │
                └──────────┘ └──────┘│  └────────┘└──────┘
                                     │
                ┌────────────────────┤
                │                    │
          ┌─────▼─────┐     ┌───────▼──────┐
          │ Executor   │     │ ONLYOFFICE    │
          │ :8082      │     │ :18088        │
          └───────────┘     └──────────────┘
                │
          ┌─────▼─────┐
          │ Lineage    │ (CLI 工具)
          │ Engine     │
          └───────────┘
```

| 模块 | 技术栈 | 端口 | 进程名 |
|------|--------|------|--------|
| **urgs-api** | Spring Boot 3 + MyBatis-Plus + Quartz | 8080 | `api` |
| **urgs-executor** | Spring Boot 3 + ProcessBuilder | 8082 | `executor` |
| **urgs-web** | React 18 + Vite + Ant Design + Tailwind | 3000(dev) / 18080(prod) | 静态文件 / Vite |
| **urgs-rag** | Python 3.10 + FastAPI + ChromaDB | 8001 | `rag` |
| **urgs-agent** | LangGraph + FastAPI + PostgreSQL + Redis | 8002 | `agent-api` / `agent-worker` |
| **sql-lineage-engine** | Python + Java GSP | CLI | CLI 工具 |
| **ONLYOFFICE** | Document Server ARM64 DEB | 18088 | `ds-docservice` / `ds-converter` |

### 外部依赖

| 组件 | 用途 | 部署方式 |
|------|------|----------|
| **MySQL 8.0+** | 主业务数据库 | 独立部署，配置连接 |
| **Neo4j 5.x** | 血缘图谱数据库 | 独立部署，配置连接 |
| **PostgreSQL 15+** | Agent 运行时存储 (checkpoint) | 可随包部署 |

| **LLM API** | RAG/Agent 大语言模型 | 外部服务，兼容 OpenAI 接口 |
| **RabbitMQ** | ONLYOFFICE 消息队列 | 随 ONLYOFFICE 安装 |

```bash
# 基础工具
sudo apt-get update

# Java 17+ (必须)
sudo apt-get install -y openjdk-17-jdk

# Python 3.10+ (RAG/Agent/Lineage)
sudo apt-get install -y python3 python3-pip python3-venv

# Node.js 18+ (前端构建)
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt-get install -y nodejs
```

### 2.3 外部服务准备

部署前确保以下外部服务已经就绪并可从目标服务器访问：

```bash
# 验证 MySQL 连通性
mysql -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p -e "SELECT 1;"

# 验证 Neo4j 连通性
curl -s "http://<NEO4J_HOST>:7474" | head -5

# 初始化 Agent PostgreSQL 数据库（如需）
sudo -u postgres psql -c "CREATE USER urgs_agent WITH PASSWORD 'change-me';"
sudo -u postgres psql -c "CREATE DATABASE urgs_agent OWNER urgs_agent;"
```

### 2.4 用户与目录准备

```bash
# 创建专用运行用户
sudo useradd -m -s /bin/bash urgs

# 创建数据目录
sudo mkdir -p /urgs-data/urgs
sudo chown -R urgs:urgs /urgs-data/urgs
```

## 4. 部署上线

### 4.1 上传解压

```bash
# 上传到目标服务器
scp dist-packages/urgs-prod.tar.gz urgs@<目标服务器>:/home/urgs/

# 登录服务器并解压
ssh urgs@<目标服务器>
tar -xzf /home/urgs/urgs-prod.tar.gz -C /home/urgs/
cd /home/urgs/urgs-prod
```

### 4.2 首次部署（推荐固定运行目录）

```bash
# 使用固定运行目录一键部署
URGS_DEPLOY_HOME=/home/urgs/urgs-app bin/deploy.sh up
```

执行过程：
1. 将包内容同步到 `/home/urgs/urgs-app`
2. 复制 `config/deploy.env` 到运行目录
3. 创建 Python 虚拟环境并安装依赖
4. 生成内部 API 认证令牌（`config/internal-api.token`，权限 600）
5. 创建所有存储目录
6. 按顺序启动所有服务

### 4.3 后续版本升级

```bash
# 升级到新版本（会备份旧文件）
cd /home/urgs/<新解压目录>
URGS_DEPLOY_HOME=/home/urgs/urgs-app bin/deploy.sh up
```

### 4.4 保留现有配置升级

如果不希望新包覆盖服务器的现有配置：

```bash
URGS_DEPLOY_HOME=/home/urgs/urgs-app URGS_DEPLOY_ENV_KEEP=1 bin/deploy.sh up
```

此时包内的新配置会保存为 `config/deploy.env.package`，方便对比差异。

## 5. 启停脚本·日常运维

### 5.1 进入运维目录

```bash
cd /home/urgs/urgs-app
```

### 5.2 deploy.sh 命令参考

| 命令 | 说明 |
|------|------|
| `bin/deploy.sh install` | 准备运行目录 / Python venv / Nginx 配置 |
| `bin/deploy.sh start` | 启动所有已启用服务 |
| `bin/deploy.sh up` | 停止 → 安装 → 启动（完整部署） |
| `bin/deploy.sh stop` | 停止所有已启用服务 |
| `bin/deploy.sh restart` | 重启所有已启用服务 |
| `bin/deploy.sh status` | 查看所有服务运行状态 |
| `bin/deploy.sh restart <服务>` | 单独重启某个服务 |
| `bin/deploy.sh nginx-config` | 查看渲染后的 Nginx 配置 |

### 5.3 单独启停服务

```bash
# 重启单个服务
bin/deploy.sh restart api        # API 服务

bin/deploy.sh restart nginx      # Nginx
bin/deploy.sh restart redis      # Redis
bin/deploy.sh restart onlyoffice # ONLYOFFICE

bin/deploy.sh stop api
```

### 5.5 本地开发启动 (start.sh)

在开发机上使用交互式菜单启动：


选择要启动的服务：

## 6. 日志与故障排查

### 6.1 日志位置

| `logs/nginx/error.log` | Nginx 错误日志 |
| `logs/nginx/access.log` | Nginx 访问日志 |

### 6.2 常用日志查看命令

```bash
# 实时查看 API 日志
tail -f /home/urgs/urgs-app/logs/api.log

# 查看最近 100 行
tail -n 100 /home/urgs/urgs-app/logs/api.log

# 搜索错误日志
grep -i "error\|exception\|fail" /home/urgs/urgs-app/logs/api.log | tail -50

# 查看 Nginx 访问日志
tail -f /home/urgs/urgs-app/logs/nginx/access.log

# 按时间段查看（前后端综合）
grep "2026-06-16 21:" /home/urgs/urgs-app/logs/api.log
```

### 6.3 故障排查流程

#### 服务无法启动

```bash
# 1. 检查服务状态
bin/deploy.sh status

# 2. 查看对应日志
tail -100 logs/<服务名>.log

# 3. 检查端口占用
lsof -i :8080  # API 端口
lsof -i :8082  # Executor 端口

# 4. 检查数据库连通性
curl -s http://127.0.0.1:8080/api/auth/profile

# 5. 检查磁盘空间
df -h /home/urgs/urgs-app
df -h /urgs-data/urgs
```

#### API 返回 502 Bad Gateway

```bash
# 1. 确认 API 进程存活
bin/deploy.sh status | grep api

# 2. 检查 Nginx 代理配置
bin/deploy.sh nginx-config | grep -A 5 "proxy_pass"

# 3. 验证 API 端口可达
curl http://127.0.0.1:8080/api/auth/profile
```

#### 登录失败

```bash
# 1. 确认数据库连通
mysql -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p -e "SELECT count(*) FROM sys_user WHERE status='active';"

# 2. 查看 API 登录日志
grep "login" /home/urgs/urgs-app/logs/api.log | tail -20

# 3. 检查 JWT token 签发
curl -X POST http://127.0.0.1:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"empId":"001001","password":"123456"}'
```

## 7. 机构管理

### 7.1 机构表结构 (`sys_org`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键 |
| `name` | VARCHAR(128) | 机构名称 |
| `code` | VARCHAR(128) | 机构编码（唯一） |
| `type` | VARCHAR(32) | 机构类型 |
| `type_name` | VARCHAR(64) | 类型名称 |
| `status` | VARCHAR(16) | 状态：`active` / `inactive` |
| `parent_id` | VARCHAR(128) | 父机构 ID（`root` 表示顶级） |
| `order_num` | INT | 排序号 |

### 8.2 系统预置角色

| 角色编码 | 名称 | 权限范围 | 说明 |
|----------|------|---------|------|

| `DATA_REPORTER` | 数据报送员 | 本机构数据 | 日常数据填报 |

### 8.3 通过 SQL 管理角色

```sql
-- 创建自定义角色
INSERT INTO sys_role (name, code, permission, status, remark)
VALUES ('业务审批员', 'BIZ_APPROVER', '辖内机构数据', 'active', '业务审批权限');

-- 为角色分配权限
INSERT INTO sys_role_permission (role_id, perm_code) VALUES
(4, 'dashboard'),              -- 仪表盘
(4, 'dash:systems'),           -- 系统概览
(4, 'dash:stats'),             -- 统计信息
(4, 'dash:notice:view');       -- 查看公告

-- 查看角色的权限
SELECT r.name, rp.perm_code
FROM sys_role r
JOIN sys_role_permission rp ON r.id = rp.role_id
WHERE r.code = 'BIZ_APPROVER';

-- 移除角色的某个权限
DELETE FROM sys_role_permission
WHERE role_id = 4 AND perm_code = 'dash:stats';

-- 停用角色
UPDATE sys_role SET status = 'inactive' WHERE code = 'BIZ_APPROVER';
```

## 10. 权限体系说明

### 10.1 认证授权架构

URGS 采用**自定义拦截器链**实现认证和授权，Spring Security 仅提供密码编码器。

```
请求进入
  │
  ├─ InternalApiAuthenticationFilter  ← 内部 API Bearer Token（/api/internal/**）
  │
  ├─ AuthenticationInterceptor         ← 从 Header/Query 提取 token，验证并注入 userId
  │   排除：/api/auth/login, /api/auth/register, /api/auth/sso/**,
  │         /profile/**, /api/internal/**, /api/webhook/**,
  │         /api/online-documents/*/onlyoffice/callback
  │
  ├─ AuthorizationInterceptor          ← 检查 @RequirePermission 注解，RBAC 鉴权
  │   排除：/api/im/**, /api/internal/**, /api/webhook/**,
  │         /api/online-documents/*/onlyoffice/callback
  │
  └─ Controller
```

### 10.2 权限码命名规范

权限码采用 `模块:资源:操作` 的层级命名规范（冒号分隔）。

## 13. 备份与恢复

### 13.1 部署自动备份

每次执行 `bin/deploy.sh up` 时，脚本会自动备份被覆盖的文件到 `backups/<timestamp>/`。

```bash
# 查看备份历史
ls -lt /home/urgs/urgs-app/backups/

# 回滚到上一个版本（手动恢复）
# 1. 停止服务
bin/deploy.sh stop

# 2. 恢复备份
cp -r backups/<timestamp>/services/api services/api
cp backups/<timestamp>/config/deploy.env config/deploy.env

# 3. 重新启动
bin/deploy.sh start
```

### 13.2 MySQL 数据备份

```bash
# 全量备份
mysqldump -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p \
  --single-transaction --routines --triggers \
  <DB_NAME> > urgs_backup_$(date +%Y%m%d_%H%M%S).sql

# 仅备份核心表（用户/角色/机构/权限）
mysqldump -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p \
  --single-transaction \
  <DB_NAME> \
  sys_user sys_role sys_role_permission sys_permission sys_org sys_system \
  > urgs_config_backup_$(date +%Y%m%d_%H%M%S).sql

# 数据恢复
mysql -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p <DB_NAME> < urgs_backup_20260615_120000.sql
```

### 13.3 配置文件备份

```bash
# 备份运行时配置
tar -czf config_backup_$(date +%Y%m%d_%H%M%S).tar.gz \
  /home/urgs/urgs-app/config/deploy.env \
  /home/urgs/urgs-app/config/internal-api.token \
  /home/urgs/urgs-app/config/services.list
```

### 13.4 定期备份脚本

创建 `/etc/cron.daily/urgs-backup`：

```bash
#!/bin/bash
BACKUP_DIR=/urgs-data/backups
mkdir -p "$BACKUP_DIR"

# MySQL 备份
mysqldump -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p'<DB_PASSWORD>' \
  --single-transaction --routines --triggers \
  <DB_NAME> | gzip > "$BACKUP_DIR/urgs_db_$(date +%Y%m%d).sql.gz"

# 保留最近 30 天
find "$BACKUP_DIR" -name "urgs_db_*.sql.gz" -mtime +30 -delete
echo "URGS backup completed: $(date)"
```

```bash
chmod +x /etc/cron.daily/urgs-backup
```

## 14. 常见问题 FAQ

### Q1: 部署后访问页面报 502

**排查步骤**：
1. `bin/deploy.sh status` 确认 API 和 Nginx 都在运行
2. `curl http://127.0.0.1:8080/api/auth/profile` 确认 API 可用
3. 检查 `config/deploy.env` 中 `API_TARGET` 配置是否正确
4. 查看 `logs/nginx/error.log` 和 `logs/api.log`

### Q2: 登录时提示"用户不存在"或"密码错误"

**排查步骤**：
1. 确认数据库中用户存在且状态为 `active`：
   ```sql
   SELECT emp_id, name, status FROM sys_user WHERE emp_id = '<工号>';
   ```
2. 管理员重置密码：
   ```bash
   curl -X POST -H "Authorization: Bearer <admin_token>" \
     http://<服务器>:18080/api/users/<用户ID>/reset-password
   ```
3. 默认密码为 `123456`

### Q3: Flyway 迁移失败

```bash
# 查看 Flyway 状态
mysql -e "SELECT * FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 10;"

# 修复失败的迁移（谨慎操作）
# 1. 手动修复数据
# 2. 删除失败记录
# DELETE FROM flyway_schema_history WHERE success = 0;
# 3. 重启 API 服务
```

### Q4: 内部 API 认证失败

内部 API 使用共享令牌 (`config/internal-api.token`) 鉴权：

```bash
# 查看令牌
cat /home/urgs/urgs-app/config/internal-api.token

# 如果令牌不同步，API 和 Executor 重新生成令牌
rm /home/urgs/urgs-app/config/internal-api.token
bin/deploy.sh restart api
bin/deploy.sh restart executor
```

### Q5: 磁盘空间不足

```bash
# 检查各目录使用量
du -sh /home/urgs/urgs-app/logs/
du -sh /home/urgs/urgs-app/backups/
du -sh /urgs-data/urgs/

# 清理旧备份
find /home/urgs/urgs-app/backups/ -maxdepth 1 -type d -mtime +7 -exec rm -rf {} \;

# 清理旧日志
find /home/urgs/urgs-app/logs/ -name "*.log" -mtime +30 -delete
```

### Q6: Agent 服务无法启动

```bash
# 检查 PostgreSQL 和 Redis 是否就绪
nc -z 127.0.0.1 5432 && echo "PostgreSQL OK" || echo "PostgreSQL DOWN"
nc -z 127.0.0.1 6379 && echo "Redis OK" || echo "Redis DOWN"

# 手动执行数据库迁移
cd /home/urgs/urgs-app/services/agent
.venv/bin/alembic upgrade head

# 查看 Agent 日志
tail -100 /home/urgs/urgs-app/logs/agent-api.log
tail -100 /home/urgs/urgs-app/logs/agent-worker.log
```
