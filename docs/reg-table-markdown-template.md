# 监管报表 Markdown 模版

## 设计目标

- 一张报表一个 Markdown，适合归档、评审、知识库收录。
- 报表首页只出现一次，字段信息以总表为主，减少重复。
- 只有复杂字段进入补充说明，兼顾简洁和可追溯。
- 码表统一在文末汇总，避免在每个字段下重复展开。

## 推荐目录结构

```text
reg-table-docs/
├── README.md
└── tables/
    ├── 001_SYS_G0101_资本充足率总表.md
    ├── 002_SYS_G0102_贷款明细表.md
    └── ...
```

| 序号 | 字段名 | 中文名 | 类型 | 数据类型 | 长度 | 主键 | 可空 | 码表 | 取值说明 | 校验规则 | 自动取数 | 备注索引 |

## 3. 补充说明

### F1 客户类型
- 字段名：`cust_type`
- 引用码表：`CUST_TYPE`（客户类型码表）
- 业务口径：客户类型按开户主体性质填写。
- 填报说明：跨境客户按客户主档映射结果上报。

**取数 SQL**

```sql
select cust_type from t_cust_info
```

| 码表编码 | 码表名称 | 使用字段数 | 说明 | 是否展开明细 |

| `AREA_CODE` | 行政区划代码 | 3 | 行政区划标准码 | 否 |

### CUST_TYPE 客户类型码表

- 使用字段：`cust_type`
- 码表说明：客户主体分类标准
- 码值数量：2

| 码值 | 名称 | 上级码值 | 描述 |

| `01` | 对公客户 | - | 企业法人客户 |

```

## 可读性建议

- 一级标题只放报表名，便于文档系统检索。
- 报表首页尽量只保留摘要，长文本放到补充说明。
- 字段信息优先压缩在“字段总表”里，一行一个字段。
- 只有有长文本、公式、SQL、代码片段的字段才进入“补充说明”。
- 码表统一在文末去重汇总，大码表只保留摘要，不逐条展开。
