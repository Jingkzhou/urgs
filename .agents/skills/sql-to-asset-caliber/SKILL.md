# SQL 到资产业务口径

把既有加工 SQL 还原为业务可读、证据可追溯的表级和字段级口径，并在确认后更新资产管理。重点是业务归纳，不是逐句翻译 SQL。

## 读取项目约束

1. 先读取当前仓库的 `AGENTS.md` 及目标目录下更具体的约束。
2. 在 URGS 仓库工作时，读取 `references/urgs-asset-contract.md`，按其中的监管资产、物理绑定和资产管理模型定位证据。
3. 需要通过 URGS API 获取监管语义时，读取 `references/regulatory-market-api.md`，使用 `scripts/regulatory_market_client.py`；不要重复手写鉴权和请求逻辑。
4. 需要定位资产、预览或回写口径时，读取 `references/asset-caliber-writeback.md`，继续使用同一客户端。
5. 生成口径前读取 `references/caliber-writing-rules.md`，使用其中的加工模式、写作规则和输出结构。
6. 如果仓库提供 SQL 解析器、血缘引擎、元数据 API、CodeGraph 或数据库只读连接，优先复用；不要仅凭文本搜索猜测资产关系。

## 输入门槛

开始前必须取得：

- 完整加工 SQL，而不是截断片段；
- 用户明确提供的监管系统编码 `systemCode`；该编码是资产查询的强制范围和唯一依据；
- 目标环境或数据源，避免同名物理表误匹配。

以下信息允许从 SQL 和监管集市中补充定位：

- SQL 方言；无法确定时从语法和项目配置推断并标注；
- 监管资产表名、字段名或指标名；
- 目标物理表，或能从 `INSERT INTO`、`MERGE INTO`、CTAS 等语句识别的目标表；
- 目标字段清单及其与监管字段/指标的映射。

禁止从系统中文名、SQL Schema、表名前缀、存储过程变量（如 `V_SYSTEM`）、程序名称或历史相似记录推断、替换监管系统编码。用户没有提供 `systemCode` 时停止资产查询并只补问该编码。

用户未提供监管表名、字段名或指标名时，不要立即要求用户补充。先限定在用户提供的 `systemCode` 内，利用 SQL 目标表、目标列、中文注释、物理绑定和监管集市搜索主动定位；只有完成候选查询后仍无法唯一确认时，才展示候选及证据并请用户选择。

缺少完整目标列清单、SQL 使用 `SELECT *`、动态 SQL 无法展开，或同名目标资产不唯一时，先补取表结构或请用户确认。不要把不完整映射写入资产。

## 工作流

### 1. 建立写回适配

先确定监管资产管理中表级口径和字段/指标级口径的实际存储位置，以及读取、更新、审计和回滚方式。在当前 URGS 项目中，按 `references/asset-caliber-writeback.md` 更新现有监管资产口径。

- 优先使用已有业务 API 或 Service；其次使用项目认可的数据库更新方式。
- 不要把 `remark`、`description`、`business_scope`、`domain` 等近义字段静默当作“业务口径”。仓库没有明确映射时，先输出“目标字段缺失/映射待确认”，不要写回。
- 只读分析不需要更新权限。真正写回前检查当前值、更新权限、审计要求和并发覆盖风险。
- 加工 SQL 只作为分析输入，禁止在生产库执行。

### 2. 解析目标与血缘

按 SQL 语句和目标表拆分分析，保留以下技术证据：

- 目标表及目标列顺序；
- CTE、子查询、源表、JOIN 条件和 UNION 分支；
- 每个目标字段的源字段与表达式；
- WHERE、HAVING、CASE、聚合、窗口、去重、空值、日期和常量规则；
- 字段映射类型：直接取值、重命名、常量、条件分类、码值转换、聚合指标、算术派生、窗口计算、去重结果或日期派生。

展开别名和 CTE 后再形成字段血缘。`INSERT ... SELECT` 按目标列与投影位置对齐；无法可靠对齐时停止该字段的自动生成并标为待确认。

### 3. 定位资产管理对象

用监管系统编码、监管表名和字段/指标名定位唯一的 `RegTable` 与 `RegElement`。记录资产 ID、类型、当前中文名、当前业务口径和更新时间。

- 始终把用户提供的 `systemCode` 带入查询；搜索结果超出该系统范围时直接排除。
- 用户提供监管表名时，以该名称为搜索锚点，并通过系统编码、物理绑定和详情证据验证唯一性。
- 用户只提供字段名或指标名时，先在指定系统内搜索元素，再根据元素所属 `tableId` 回溯监管表并读取完整 `table-bundle`。
- 用户未提供监管表、字段或指标名称时，从 SQL 目标物理表和目标列开始，依次匹配物理绑定、精确名称、业务编码和中文注释；对候选表读取 `table-bundle` 后再确认。
- 选定监管表后，枚举其全部 `FIELD` 和 `INDICATOR` 元素；优先分析本次 SQL 实际赋值、计算、过滤或关联到的元素，不要求用户逐个报出名称。

- 目标监管资产不存在时，报告缺口，不要顺带创建资产。
- SQL 目标字段无法通过物理绑定或明确映射关联到监管元素时，单独列出“结构差异”。
- 资产字段未被本次 SQL 赋值时，不推测其口径，也不清空已有内容。

### 4. 获取监管语义证据

按以下优先级寻找监管资产：

1. 已维护的物理表/字段绑定；
2. 已确认的监管表关系或映射；
3. 同一监管系统内的精确表名、字段名或业务编码；
4. 中文名和业务口径语义相似度，仅用于提出候选。

对决定结论的候选，读取监管表描述、表业务口径、填报说明、监管字段/指标描述、公式、值域、码表及有效码值。涉及码值时必须读取正式码表说明，不能把 `01`、`A`、`N` 等代码按常识解释。

在 URGS 中，先使用客户端的 `search` 命令定位候选，再对确认的表使用 `table-bundle`。若返回 `complete=false` 或非空 `warnings`，把缺失证据列为待确认，不对受影响字段自动回填。

仅名称相似、没有绑定或精确映射的候选，置信度设为“低”，只进入待确认项，不参与自动写回。

#### 指标查询与分析

- 用用户提供的 `systemCode` 和指标名、目标列名、SQL 中文注释或表达式业务词搜索指标候选，保留类型为 `INDICATOR` 的元素；没有指标名时也要检查候选表的指标列表。
- 对候选指标读取元素详情及所属表的 `table-bundle`，获取指标公式、取数 SQL、代码片段、填报说明、校验规则、值域、码表、物理字段绑定和当前业务口径。
- 展开 SQL 中与指标相关的聚合、算术表达式、`CASE`、窗口、去重、日期和过滤条件，与监管公式逐项核对，分析统计对象、粒度、周期、分子、分母、单位、精度、正负号和异常处理。
- SQL 公式与监管指标公式一致且绑定明确时形成高置信度口径；部分一致或缺少直接绑定时形成中置信度草稿；存在冲突、公式缺失或仅名称相似时列为待确认，不自行裁决。

### 5. 归纳业务规则

先生成字段级规则，再汇总表级规则。

字段/指标级至少回答：

- 该字段表示什么业务事实或指标；
- 来自哪些业务数据；
- 适用哪些对象、状态、日期和机构范围；
- 如何计算、分类、汇总、去重或取最新；
- 空值、默认值、异常值和码值分别如何处理；
- 指标的统计粒度、周期、单位、聚合方式及必要的分子/分母。

表级至少回答：

- 该表承载的业务对象和目的；
- 一行数据代表什么粒度；
- 来源范围、纳入/排除范围、统计时点；
- 关键关联、汇总和去重原则；
- 与监管表、监管指标或值域的关系。

不要把所有 SQL 细节堆进表级口径。表级内容应概括稳定业务规则，字段级内容承载具体计算。

### 6. 分离事实、推断与缺口

为每条口径记录证据和置信度：

- **高**：目标字段映射明确，并有物理绑定或监管口径/码值直接支持；
- **中**：SQL 映射明确，业务含义由资产中文名、上下文和多个一致证据支持，但缺少直接绑定；
- **低**：主要依赖名称相似、常识或不完整 SQL。

高、中置信度内容可以进入回填草稿；低置信度内容必须写成“待确认”，不得包装成确定事实。SQL 与监管资产冲突时同时保留双方证据，不自行裁决。

### 7. 生成回填预览

按 `references/caliber-writing-rules.md` 的格式输出：

- 表级业务口径草稿；
- 字段/指标级业务口径草稿；
- 原值与新值差异；
- 每项监管证据、SQL 证据和置信度；
- 结构差异、冲突和待确认项；
- 计划使用的更新通道与回滚方式。

已有非空口径默认采用“保留已确认内容，补充新证据”的合并策略。发现语义冲突时不要覆盖，先请求确认。禁止只因为新文本更长就替换原值。

### 8. 确认后写回

展示完整预览后再写回。用户在当前请求中明确要求直接应用且已给出目标字段映射时，可以把该指令视为写回授权；仍要先调用 `caliber-preview` 并保存可审计差异。

- 只更新本次已确认的目标表和目标字段。
- 使用带更新条件或版本检查的方式，避免覆盖他人的并发修改。
- 维护项目要求的变更记录、操作人、需求号或审计字段。
- 批量写回优先使用事务；无法使用事务时先生成可执行的回滚内容。
- 不修改监管资产本身，除非用户明确把监管资产也纳入范围。
- 在 URGS 中只通过 `caliber-apply --confirm` 调用专用回写接口，不调用通用监管资产保存接口，也不直接执行数据库更新语句。

### 9. 回读验证

写回后使用 `asset-table` 重新读取目标资产并逐项核对：

- 实际保存值与预览一致；
- 未确认字段未被修改；
- 原有口径没有意外丢失；
- 审计记录完整；
- 待确认项仍保留在报告中，而不是混入确定口径。

最终报告更新成功、跳过、冲突和失败的数量，并列出可定位的资产 ID。

## 硬性约束

- 不推断监管系统编码；`systemCode` 必须由用户明确提供，并原样用于资产查询范围。
- 不因用户未提供监管表名、字段名或指标名就放弃查询；先在指定系统内主动搜索、回溯所属表并分析候选元素。
- 不逐句翻译 SQL，不把函数名、别名和临时表名堆成业务描述。
- 不凭同名字段猜 JOIN、监管映射或码值含义。
- 不执行用户提供的加工 SQL。
- 不在没有预览、目标字段映射或写回授权时修改资产。
- 不覆盖无法解释来源的已有口径。
- 不把“待确认”写成确定结论。
